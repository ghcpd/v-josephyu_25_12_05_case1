# DEFECTS FOUND - Flask Login Application

## Summary
Testing the README.md against actual implementation revealed multiple discrepancies between documentation and code behavior. Below are all identified defects with reproduction procedures and traces.

---

## DEFECT #1: Command-Line Arguments Not Supported
**Severity:** HIGH  
**Location:** README.md, Section 3.3 - "Start the App"  
**Reproduction Procedure:**
1. Activate virtual environment: `.\\.venv\\Scripts\\Activate.ps1`
2. Run command from README: `python app.py --host=0.0.0.0 --port=8080`

**Expected Behavior (from README):**
```powershell
Binds to http://0.0.0.0:8080/ in this configuration
Command-line flags --host / --port can be used to change the bind address and port
```

**Actual Behavior:**
- App starts on default `http://127.0.0.1:5000/` 
- `--host` and `--port` arguments are ignored
- No error message about unknown arguments

**Error Trace:**
```
(Flask app starts with debug=True)
 * Running on http://127.0.0.1:5000
 * Press CTRL+C to quit
```

**Code Reference:**
- File: `app.py`
- Code: `if __name__ == '__main__': app.run(debug=True)`
- Issue: `app.run()` called without parameters; doesn't parse command-line arguments

**Fix:** Either:
1. Remove the command-line examples from README, OR
2. Implement argument parsing in app.py using argparse or Flask's Click integration

## DEFECT #5: Session Storage Method Documented Incorrectly
**Severity:** MEDIUM  
**Location:** README.md, Section 4.3 - "Sessions & Login"  
**Reproduction Procedure:**
1. Review README section 4.3
2. Check app.py and auth.py for Redis configuration

**Expected Behavior (from README):**
```
Sessions are stored server-side in Redis for better scalability.
A local in-memory fallback session store may be used for development if Redis is not configured.
To run the app in stateless API-only mode without sessions, set SESSIONLESS_MODE=true
```

**Actual Behavior:**
```
Sessions use Flask's default secure cookie-based session store (Werkzeug)
No Redis configuration found in code
No SESSIONLESS_MODE environment variable handling
```

**Code References:**
- File: `app.py` - No Redis imports or configuration
- File: No environment variable checks for SESSIONLESS_MODE
- File: `auth.py` - Uses standard Flask-Login session management

**Implementation Reality:**
```python
# app.py uses default Flask session handling (secure cookies)
login_manager = LoginManager()
login_manager.login_view = 'auth.login'
login_manager.init_app(app)
# No Redis configuration present
```

**Issue:**
- README promises Redis but Flask-Login uses secure cookies by default
- SESSIONLESS_MODE is mentioned but never implemented
- Misleading documentation about scalability

## DEFECT #7: Database Migration Documentation Missing
**Severity:** LOW  
**Location:** README.md - No section on database migrations  
**Issue:** 
- README mentions automatic table creation via `init_db(app)` 
- But there's a workaround for migration existing DBs with missing email column
- This migration logic is not documented

**Code Reference:**
```python
# models.py, lines 53-60
try:
    cur.execute('SELECT email FROM users LIMIT 1')
except sqlite3.OperationalError:
    cur.execute('ALTER TABLE users ADD COLUMN email TEXT')
    # Note: existing rows will have NULL email
```

**Issue:** Developers need to know about this migration for legacy databases
